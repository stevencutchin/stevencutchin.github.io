MySQL Sandbox Lab Setup

Deploying and using your own MySQL server on the Onyx cluster

Run your own MySQL database server in a sandbox on Onyx — one per student, with no conflicts — and connect to it from Workbench, the command line, or Java.

On this page

  1. Set up the MySQL server on Onyx
  2. Administer the database server
  3. Use the MySQL database

We will run the MySQL database server in a sandbox. This lets many students each run their own database server on Onyx without conflicting with one another or with the main database server, and it gives you an elementary taste of life as a Database Administrator (DBA). Everything below happens on the Onyx server: from a lab workstation, open a terminal and run ssh onyx; you can also connect from your own laptop.

1  ·  Set up the MySQL server on Onyx

Step 1 — deploy the database

Run the following command on the Onyx command line. When prompted, enter a password for your database.

deploydb.sh

Choose your database password carefully

Use only numbers and letters — no special characters. Do not reuse your Onyx password.

Step 2 — read the output

You will see output like the following. Your port number, home directory, and password will differ.

Sample output[benjaminpeterson@onyx:~]$ deploydb.sh

Port number: 50004

Two things to note

Run deploydb.sh on the Onyx server, not on the compute nodes. And write down the port number from the output — you will need it every time you connect from MySQL Workbench or the command line.

2  ·  Administer the database server

2.1   Database basics

Your database lives in /home/$USER/sandboxes/msb_9_4_0/, where $USER is your Onyx login name. Change into the sandbox folder:

cd /home/$USER/sandboxes/msb_9_4_0/

Run dbdeployer usage single to see the full list of operating instructions. The commands you will use most often are:

CommandWhat it does
./statusCheck whether your database server is running.
./stopStop the server. (You normally won't — a server is meant to stay running.)
./startStart the server if it was stopped.
./restartStop and restart the server.
./clearDelete all database information.

./clear destroys your data

The clear command deletes everything in the database. Do not run it unless you truly do not care what is stored there.

Can't connect?

Run ./status first to confirm the server is running. That resolves the majority of connection problems.

2.2   Troubleshooting

Two scripts help with database problems. Both run on Onyx from the command line:

ScriptWhat it does
dbtroubleshoot.shWalks through the common causes of a database that won't start, and offers to delete and recreate it if needed.
deletedb.shCleanly deletes your database. You can then recreate it as described in Section 1.

3  ·  Use the MySQL database

3.1   MySQL Workbench in the lab

Set up the connection once, then reuse it. From a lab workstation, connect with ssh onyx, then launch Workbench (on Onyx, not on the nodes):

mysql-workbench

Once it launches, click the + next to MySQL Connections and fill in the Setup New Connection window. Leave the other boxes at their defaults:

  • Connection Name: CS410 Database (name it anything you like)
  • Port: the port number provided during installation
  • Username: msandbox

Click Test Connection, then Connect Anyway, and enter the password you set during installation. A correct setup reports a successful test. Click OK to save. From now on, just click your connection's name to open the database — no need to set it up again.

3.2   MySQL Workbench from home

To work from your own machine, download and install MySQL Community Workbench for your operating system. The MySQL site will explain any additional software it needs.

Connect to the VPN first

Before trying the connection below, connect to the university VPN. See VPN Setup for Accessing Onyx.

Then start Workbench and set it up to reach your sandbox over an SSH tunnel:

  • SSH: connect to onyx.boisestate.edu on port 22 using your Onyx login.
  • Database: connect to localhost on the port from your installation (for example 50004), with msandbox as the database user.

For more detail, see MySQL's connecting over SSH documentation.

3.3   MySQL command-line interface

To use the command-line client, change into the sandbox folder and run its ./use script:

cd $HOME/sandboxes/msb_9_4_0/
./use

3.4   JDBC access from Java programs

Java Database Connectivity (JDBC) is the standard API for a Java program to talk to a database. To use it with MySQL you need a connector, which is already installed on Onyx:

/opt/mysql/mysql-connector-j-9.4.0.jar

Add the connector to your CLASSPATH so the Java runtime can find it, by appending this line to the end of your ~/.bashrc (the file that runs when you log in to Onyx):

export CLASSPATH=/opt/mysql/mysql-connector-j-9.4.0.jar:.:$CLASSPATH

Keep it on one line

The export line above must be a single unbroken line in your .bashrc. You can edit the file with kwrite ~/.bashrc; log in again for the change to take effect.

Example programs

Two example programs demonstrate connecting to a database and running queries from Java: Example1JDBC.java and Example2JDBC.java. Compile and run them from the command line:

Sample run[amit@onyx example1-jdbc]$ javac Example1JDBC.java
[amit@onyx example1-jdbc]$ java Example1JDBC
JDBC driver loaded
Database [test db] connection succeeded!
1234:Data:data:123 Main Street:Boise
999:Random:Last:101 Bogus Basin Road:Boise
Database [test db] connection closed

You can also use them in an Eclipse Java project. Add mysql-connector-j-9.4.0.jar on the Libraries tab as an External JAR in the new-project wizard; browse to /opt/mysql to find it. The full official guide is the MySQL Connector/J documentation.
