Part 4 (22 points): B+trees, Indexes, and Normalization

4.1

The B+tree below indexes the column weight. Each node shown is one page, and the leaves are chained left to right. (4 pts)

The engine evaluates WHERE weight BETWEEN 26 AND 49 using this index. Answer all three parts:

  1. List the nodes that are read, in the order they are read.
  2. How many index pages are read in total?
  3. Which key ends the scan, and which leaf is it on? Explain why that leaf has to be read even though it contributes no rows to the answer.

Page 20

4.2

A B+tree indexes a table of 50 million rows, and each index page holds roughly 250 entries. The tree is 4 levels deep. Explain why the tree stays this shallow, and state how many index page reads an equality lookup such as WHERE weight = 44 costs. (2 pts)

4.3

Consider the following query:

SELECT issue_id, title FROM issue WHERE opened_on BETWEEN '2026-01-01' AND '2026-03-31';

(a) Which type of index is more convenient to create (HASH, BTREE, or FULLTEXT) to speed up this query, on which attribute, and why? (b) Would that same index speed up WHERE YEAR(opened_on) = 2026? Explain. (3 pts)

4.4

Consider the following query:

Which type of index is more convenient to create (HASH, BTREE, or FULLTEXT) to speed up the query computation? Why? On which attribute(s) should the index be created? (3 pts)
