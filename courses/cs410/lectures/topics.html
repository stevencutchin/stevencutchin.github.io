Course topics in depth

The seven catalog topics, expanded into nine teaching units and keyed to the assigned Elmasri & Navathe chapters. Each unit lists what it covers and where it is graded, so you can trace any topic straight to its homework or exam.

U0

Foundations — what a DBMS is and why

Ch 1–2

Why the file-at-a-time habits from CS 321 stop scaling, and what a database system adds on top of raw data structures.

  • File-processing vs. the database approach; what a DBMS buys you
  • Data abstraction; the value of program–data independence
  • Data models, schemas vs. instances
  • The three-schema architecture and data independence
  • DDL and DML; client/server DBMS architecture; classifying DBMSs
Slides:
  • Introduction to Database Systems
  • DB System Concepts & Architecture

Assessed by: Midterm 1

U1

Conceptual design — the ER and EER models

Ch 3–4

Turning a description of the world into a diagram before any tables exist.

  • Entities; attribute types (simple/composite, single/multi-valued, derived, key)
  • Entity types vs. entity sets
  • Relationship types, degree, roles; cardinality ratios (1:1, 1:N, M:N)
  • Participation constraints (total vs. partial)
  • Weak entity types and identifying relationships
  • Chen and Elmasri–Navathe notation
  • EER: specialization/generalization, attribute inheritance
  • Disjoint vs. overlapping, total vs. partial; union types (categories)
Slides:
  • ER I — Entities, Attributes, Keys
  • ER II — Relationships, Cardinality, Weak Entities
  • EER — Specialization & Generalization

Assessed by: HW1Midterm 1

U2

The relational model and ER-to-relational mapping

Ch 5, 9

The formal model the rest of the course runs on, and the algorithm that gets you there from a diagram.

  • Relations, tuples, attributes, domains; schema vs. instance
  • Key constraints; entity integrity; referential integrity
  • Primary, candidate, and foreign keys; NULLs
  • The 7-step ER→relational mapping algorithm
  • Mapping EER constructs (specialization options, union types)
Slides:
  • The Relational Model — Relations, Keys, Integrity

Assessed by: HW1Midterm 1

U3

Relational algebra

Ch 8

The procedural language underneath SQL — what a query actually computes, step by step.

  • Unary operations: SELECT (σ), PROJECT (π), RENAME (ρ)
  • Set operations (∪, ∩, −, ×)
  • JOIN (theta, equijoin, natural) and DIVISION
  • Aggregation and grouping; outer joins
  • Building query trees; relational calculus as the declarative counterpart

Assessed by: HW2Midterm 1

U4

SQL

Ch 6–7

The commercial language that implements the relational model, from table definitions to complex queries.

  • DDL: CREATE TABLE, data types, constraints (PK, FK, CHECK, DEFAULT)
  • Retrieval: SELECT-FROM-WHERE, aliasing, DISTINCT, ordering
  • Set operations; INSERT / UPDATE / DELETE
  • Nested and correlated subqueries; EXISTS / ANY / ALL
  • Joined tables and outer joins in SQL
  • Aggregation with GROUP BY / HAVING
  • Views and updatability; assertions and triggers; ALTER

Assessed by: HW2Midterm 1Final Project

U5

Database access from applications

Ch 10–11

Getting a real program to talk to the database — and the security traps that come with it.

  • The impedance mismatch; embedded vs. dynamic SQL; cursors
  • API-based access (JDBC / ODBC concepts)
  • Stored procedures; SQL/PSM
  • Connecting an application to a DB; transactions from application code
  • Parameterized queries and SQL injection

Assessed by: Midterm 2Final Project

U6

Functional dependencies and normalization

Ch 14–15

The theory that tells you whether a schema is well-designed, and the algorithms that fix it when it isn't.

  • Informal design guidelines; update anomalies
  • Functional dependencies; Armstrong's axioms; attribute closure; minimal cover
  • 1NF, 2NF, 3NF (partial and transitive dependencies)
  • Boyce–Codd Normal Form (BCNF)
  • Lossless-join and dependency-preservation properties
  • 3NF and BCNF decomposition algorithms
  • Multivalued dependencies and 4NF (brief 5NF)

Assessed by: HW3Midterm 2

U7

Storage and indexing

Ch 16–17

Why disk I/O dominates cost, and the structures that make lookups fast — the B+-tree you met in CS 321, now doing real work.

  • Disk, blocks, records; heap and sorted file organizations
  • Static and dynamic hashing (extendible, linear)
  • The disk-I/O cost model — why one structure beats another
  • Ordered indexes: primary, clustering, secondary; multilevel indexes
  • B-trees and B+-trees; why B+-trees for databases
  • Index selection and physical database design

Assessed by: HW3Midterm 2

U8

Transactions, concurrency, and recovery

Ch 20–22

How a database stays correct when many users hit it at once and the power goes out mid-write.

  • Transaction concept; ACID properties
  • Concurrency anomalies; schedules; conflict serializability; precedence graphs
  • Two-phase locking and variants; shared/exclusive locks; deadlock
  • Timestamp ordering; MVCC and isolation levels (brief)
  • Recovery: the system log; write-ahead logging; checkpoints
  • ARIES recovery (conceptual overview)

Assessed by: Final
