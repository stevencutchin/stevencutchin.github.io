Orientation

What SQL is — and isn't

Declarative. You state what you want, like relational calculus; the DBMS decides how to compute it.

A standard. Keywords are case-insensitive, whitespace is free, and every statement ends in a semicolon. Vendors add extensions, but the core is portable.

Three sub-languages. DDL defines structure, DML reads and changes data, DCL grants access.

SQL is a multiset language

Unlike the algebra, a SQL table and a query result are bags — duplicates are kept unless you ask for DISTINCT. This one difference explains a surprising amount of later behavior.

DDL · 1

CREATE TABLE

A table definition lists columns, each with a name and a data type, followed by any constraints.

The DBMS records this in its catalog and enforces it from then on: every row inserted must satisfy the declared types and constraints.

Companion statements

DROP TABLE removes a table and its data; ALTER TABLE adds or changes columns and constraints later (Unit 4, lecture 3).

CREATE TABLE STUDENT (
  StudentID  CHAR(5)      PRIMARY KEY,
  Name       VARCHAR(50)  NOT NULL,
  Major      VARCHAR(20)
             DEFAULT 'Undeclared',
  GPA        DECIMAL(3,2)
);

One column per line reads best; the PK is declared inline here.

DDL · 2

Choosing a data type

A type is the column's domain — the set of legal values. Pick the tightest one that fits; it's your first line of data quality.

  • Numeric — INT, SMALLINT, DECIMAL(p,s), FLOAT.
  • Text — CHAR(n) fixed, VARCHAR(n) variable.
  • Date/time — DATE, TIME, TIMESTAMP.
  • Boolean — BOOLEAN (where supported).

CHAR vs VARCHAR, and money

Use CHAR only for truly fixed-width codes; VARCHAR otherwise. Never store money as FLOAT — rounding error accumulates. Use DECIMAL for anything exact.

DDL · 3 — constraints

Key constraints: PRIMARY & FOREIGN KEY

PRIMARY KEY enforces entity integrity: unique and never NULL. Use a table-level clause for a composite key.

FOREIGN KEY enforces referential integrity: the value must match a primary key in the referenced table (or be NULL).

A referential action says what happens when the referenced row is deleted or updated:

  • ON DELETE CASCADE — delete the dependent rows too.
  • ON DELETE SET NULL — blank the foreign key.
  • Default is RESTRICT — refuse the delete.
CREATE TABLE ENROLLMENT (
  StudentID CHAR(5),
  CourseID  CHAR(8),
  Grade     CHAR(1),
  PRIMARY KEY (StudentID, CourseID),
  FOREIGN KEY (StudentID)
     REFERENCES STUDENT(StudentID)
     ON DELETE CASCADE,
  FOREIGN KEY (CourseID)
     REFERENCES COURSE(CourseID)
);

The composite PK and both FKs are the M:N mapping in SQL.

DDL · 4 — constraints

NOT NULL, UNIQUE, CHECK, DEFAULT

  • NOT NULL — a value is required.
  • UNIQUE — no duplicates, but NULL is allowed; use it for alternate (candidate) keys.
  • CHECK — a per-row condition the DBMS enforces.
  • DEFAULT — value used when none is supplied.

Name constraints (CONSTRAINT chk_gpa …) so error messages point you to the rule that failed.

CREATE TABLE STUDENT (
  StudentID CHAR(5)  PRIMARY KEY,
  Name      VARCHAR(50) NOT NULL,
  Email     VARCHAR(80) UNIQUE,
  Major     VARCHAR(20)
            DEFAULT 'Undeclared',
  GPA       DECIMAL(3,2)
    CHECK (GPA >= 0.0 AND GPA <= 4.0)
);

Email is a candidate key; CHECK keeps GPA in range.

DML · the query block

SELECT-FROM-WHERE is π, σ, ×

The basic query has three clauses, and each is an algebra operator you already know:

  • FROM names the relations (a product if several).
  • WHERE is the selection σ — the row filter.
  • SELECT is the projection π — the columns to keep.

πName,Major( σGPA>3.6(STUDENT) )

SELECT Name, Major
FROM   STUDENT
WHERE  GPA > 3.6;

The lifelong gotcha

SQL's SELECT does the projection, and WHERE does the algebra's select. The names cross over — say it out loud once and it sticks.

Filtering rows

Writing the WHERE condition

Combine comparisons (= < > <= >= <>) with AND, OR, NOT. Several shorthands make conditions readable:

  • BETWEEN a AND b — inclusive range.
  • IN (…) — membership in a list.
  • LIKE — pattern match: % any run of characters, _ a single one.
  • IS NULL — test for a missing value.
-- CS or Math students, GPA at least 3.5
SELECT Name
FROM   STUDENT
WHERE  Major IN ('CS', 'Math')
  AND  GPA BETWEEN 3.5 AND 4.0;

-- names beginning with A
SELECT Name FROM STUDENT
WHERE  Name LIKE 'A%';

Shaping the output

DISTINCT, ORDER BY, and aliases

DISTINCT removes duplicate result rows — recovering the algebra's set behavior on demand.

ORDER BY sorts the output, ASC (default) or DESC; order otherwise is not guaranteed.

AS renames a column or table in the output — SQL's rename (ρ), handy for computed columns and self-joins later.

SELECT DISTINCT Major
FROM STUDENT;

SELECT Name, GPA AS grade_point
FROM   STUDENT
ORDER BY GPA DESC;

DISTINCT dedupes; ORDER BY sorts; AS relabels.

The subtle part

NULL and three-valued logic

A comparison with NULL yields neither true nor false but UNKNOWN. SQL logic has three values, and WHERE keeps a row only when the condition is true — never when it is UNKNOWN.

So GPA = NULL is always UNKNOWN and matches nothing. Test missing values with IS NULL instead.

Consequences to remember

  • x = NULL is never true — use IS NULL.
  • A row where the test is UNKNOWN is excluded.
  • NOT UNKNOWN is still UNKNOWN.
  • Aggregates skip NULLs (more in lecture 3).

Reference

The SELECT statement, clause by clause

SELECTcolumns to keep — the projection π (with DISTINCT to dedupe)
FROMthe relations — a product when more than one
WHERErow condition — the selection σ
GROUP BYform groups for aggregation — lecture 3
HAVINGcondition on groups — lecture 3
ORDER BYsort the final output (ASC / DESC)

Written vs. evaluated order

You write SELECT first, but the DBMS conceptually evaluates FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY. That's why a SELECT alias can't be used in WHERE.

Judgment

Pitfalls & tips

  • SELECT is π, WHERE is σ. The crossover from the algebra names trips up everyone once. Name it now and move on.
  • Results keep duplicates. If a count looks too high, you wanted DISTINCT. SQL is a bag, not a set.
  • = NULL never matches. Reach for IS NULL / IS NOT NULL every time.
  • Quote strings with single quotes. Double quotes mean an identifier in standard SQL, not a string.
  • Match FK and PK types. A CHAR(5) key referenced by a CHAR(8) foreign key is a definition-time error, not a runtime one.
